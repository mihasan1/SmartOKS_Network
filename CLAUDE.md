## 1. Що це за проєкт

**SmartOKS — Network Planner** — браузерний візуальний конструктор локальних мереж і планувальник приміщень (аналог Cisco Packet Tracer). Малюєш кімнати, розставляєш пристрої, з'єднуєш кабелями або по Wi-Fi, роздаєш IP, перевіряєш зв'язність через ping-симуляцію.

- **Мова спілкування з користувачем:** українська.
- **Продакшн:** https://smartoks-network.vercel.app
- **GitHub:** https://github.com/mihasan1/SmartOKS_Network (гілка `main`, тег `v1.0.0`).

### Стек
- **Бекенд (лише локальний dev):** Node.js + Express (`server.js`) — роздає статику з `public/` і зберігає проєкти в `data/*.json`.
- **Прод:** Vercel — статика з `public/`, а API — serverless-функції в `api/` (пишуть у ефемерний `/tmp`).
- **Фронтенд:** HTML5 **Canvas** + **чистий JavaScript, БЕЗ фреймворків**. Уся логіка рендеру, взаємодії, мережі — вручну на canvas.
- **Залежності:** лише `express` (див. `package.json`). Фронтенд без залежностей і без збірки — файли віддаються як є.

### Команди
```bash
npm install     # встановити express
npm start       # node server.js  → http://localhost:3000
npm run dev     # node --watch server.js (автоперезапуск)
```
- **Білду немає** (немає bundler/транспіляції). Правки в `public/*` видно одразу після перезавантаження сторінки.
- **Лінту/тестів немає.** Перевірка синтаксису: `node --check public/app.js`.
- **Деплой:** `npx vercel deploy --prod --yes` (Vercel CLI вже авторизований локально; проєкт злінкований у `.vercel/`, який у `.gitignore`).

### Змінні оточення
- `PORT` — порт локального Express-сервера (типово `3000`). Використовується у `server.js`.
- Секретів/ключів у проєкті **немає**. Vercel env-змінних не потребує. GitHub-пуш і Vercel-деплой авторизуються локально (Git Credential Manager / Vercel CLI).

### Структура
```
server.js               # локальний Express (dev): статика + CRUD проєктів у data/*.json
vercel.json             # framework:null, outputDirectory:public — статика + api/
api/projects.js         # serverless: GET список проєктів (з /tmp)
api/projects/[name].js  # serverless: GET/PUT/DELETE один проєкт (у /tmp)
public/index.html       # розмітка: топбар, палітра, канвас, інспектор, оверлеї
public/style.css        # CSS-змінні тем (light/dark), картки, адаптивність, оверлеї
public/i18n.js          # словник UA/EN + t(), applyI18n(), setLang()
public/icons.js         # SVG-іконки (Lucide-стиль) + svgInline()/svgDataURL()
public/devices.js       # каталог типів пристроїв (DEVICE_TYPES, DEVICE_ORDER, devName)
public/help.js          # модальне вікно довідки (F1), двомовне
public/app.js           # ЯДРО (~1800 рядків): canvas-рушій, взаємодія, мережа, історія, експорт
```

### Що зроблено і працює (усе перевірено)
- **Планувальник:** кімнати та стіни, зміна розміру ручками; пристрої всередині кімнати рухаються разом із нею.
- **10 типів пристроїв:** pc, laptop, server, printer, switch, hub, router, ap, camera, nvr. Індивідуальні: IP, mask, gateway, MAC, к-сть портів, Wi-Fi (вкл/викл + радіус), живлення, DHCP (у сервера).
- **Кабелі:** мідь/оптика, ліміт портів з індикаторами, **ортогональна трасування A\*** з обходом пристроїв, скруглені кути. **Власний колір** кабелю + **ручне редагування згинів** (вузли: тягати, додавати на «+», видаляти подвійним кліком, «Випрямити» → назад до A\*).
- **Wi-Fi:** коло покриття з регульованим радіусом (тягнути маркер або число); бездротова асоціація в радіусі роутера/точки доступу.
- **Мережа:** Авто-IP (`192.168.X.0/24` по сегментах), DHCP-сервер, маски, шлюзи, виявлення конфліктів IP (червоний ⚠), ping-симуляція (пакет летить уздовж кабелю).
- **Редагування:** undo/redo (Ctrl+Z/Y, знімки стану, 100 кроків), мультивиділення (рамка/Shift), копіювання (Ctrl+C/V), зсув стрілками, пан/зум.
- **Експорт:** PNG (offscreen hi-res), експорт/імпорт `.json`, друк; збереження на сервер + автосейв у localStorage. **Індикатор прогресу** (спінер+час+смужка) на цих операціях.
- **UI:** світла/темна теми (перемикач, зберігається), i18n UA/EN, професійні SVG-іконки скрізь (жодних emoji в чромі), довідка (F1), повна адаптивність (десктоп/планшет/мобільний).

### Відомі проблеми / обмеження
1. **Продуктивність на великих схемах.** `ensureRoutes()` перераховує A\*-маршрути для ВСІХ кабелів при будь-якій зміні позицій. ~505 мс на 800 пристроях / 479 кабелях → перетягування лагає на великих імпортованих схемах. **Не оптимізовано.**
2. **Серверне збереження на Vercel ефемерне** (`/tmp`) — кнопки «Зберегти»/«Відкрити» в проді ненадійні між запусками serverless. Реальне збереження = localStorage-автосейв + експорт/імпорт `.json`.
3. Скриншоти й `ResizeObserver`/подія `resize` **не спрацьовують у preview-інструменті** (обмеження headless CDP) — це артефакт середовища, у реальних браузерах усе працює.

## 3. Домовленості та рішення (те, чого не видно з коду)

### Архітектурні рішення
- **Чистий Canvas + vanilla JS, без фреймворків** — свідомо. Уся модель у пам'яті, рендер вручну.
- **JointJS/GoJS свідомо ВІДХИЛЕНО.** Користувач пропонував їх для якісних зв'язків. JointJS — SVG/DOM (не пасує до нашого canvas), GoJS — платна ліцензія. Замість цього реалізовано **власну ортогональну A\*-трасування** — та сама можливість, рідно для рушія. Не тягни ці бібліотеки.
- **Модель даних:** `model = { rooms, walls, devices, cables }`; `serialize() = { model, nextId, view }`. Це і є формат `.json` експорту/збереження.
- **Undo/redo — повні знімки** (JSON усього стану) через `commit()`, а не дельти. Простіше й надійніше на цьому масштабі. Дискретні дії викликають `commit()`; текстові поля — на `change`, не на кожну літеру.

### Формат JSON (важливо — часто питають; для ChatGPT-аналізу)
- `devices[]`: `id, kind, x, y` (px, крок сітки 24), `name, ip, mask, gateway, mac, on, dhcp`; опційно `ports` (перекриття к-сті портів), `wifi` (перекриття Wi-Fi-здатності), `range` (радіус Wi-Fi px, типово 190).
- `cables[]`: `id, a, b` (`a`/`b` = `id` пристроїв), `type` (`"copper"`/`"fiber"`); опційно `color` (hex), `waypoints` (масив `{x,y}` вузлів згину — якщо є, A\* не застосовується).
- `rooms[]`: `id, x, y, w, h, name, color`. `walls[]`: `id, x1, y1, x2, y2`.
- Пересилають трафік лише forward-пристрої: switch, hub, router, ap, nvr. Зв'язність = кабелі + Wi-Fi-асоціації (пристрій з `wifi` у радіусі увімкненого forward-Wi-Fi-джерела).

### Конвенції коду
- Коментарі — переважно українською (частина старих — російською; не критично).
- Файли фронтенду завантажуються в порядку: `i18n.js → icons.js → devices.js → help.js → app.js`. Порядок важливий (залежності через `window.*`).
- Сітка `GRID = 24` px. Координати пристроїв прив'язані до неї (`snap()`).

### «Підводні камені» (реальні баги, які вже ловили — не повторюй)
- **Клавіатура: використовуй `e.code`, НЕ `e.key`.** При кириличній розкладці `e.key` дає «я»/«н» замість z/y → скорочення ламаються. Уся клавіатура на `e.code` (`KeyZ`, `KeyV`…).
- **Сітка трасування `RG` МАЄ бути дільником `GRID` (24).** Зараз `RG = 12`. Інакше точки виходу кабелю не лягають на вузли → на кінцях з'являються «закарлючки». Не став 16.
- **`applyI18n()` робить `textContent`** — це стирає вкладений SVG у кнопках. Тому підписи кнопок загорнуті в `<span class="lbl">`, а `data-i18n` стоїть на цьому span, НЕ на кнопці. Іконки інжектяться в `[data-icon]` на старті.
- **НЕ став CSS `transition` на `background` з `var()` у `body`** — давало застряглий колір при перемиканні теми (прибрано).
- **Дві теми паралельно:** CSS-змінні (`:root` / `:root[data-theme="dark"]`) для інтерфейсу + окремий JS-об'єкт `THEMES.light/dark` (`TH`) для кольорів canvas. Додаючи колір — онови ОБИДВА.
- **Інпут `#proj-name` обов'язковий** — `projName()` і збереження на нього спираються. Колись його прибрали під час редизайну → зламався експорт JSON/PNG/друк. Не видаляй.
- **`Array.forEach(fn)` передає індекс 2-м аргументом.** Не передавай напряму функцію з 2-м параметром (був баг: `model.rooms.forEach(drawRoom)`, де `drawRoom(r, draft)` отримував індекс у `draft`). Використовуй `forEach((x) => fn(x))`.
- **Прогрес-оверлей — yield через `setTimeout`, НЕ `requestAnimationFrame`** (rAF не спрацьовує у фоновій вкладці → зависання). Анімація спінера/смужки — на CSS-transform (крутиться навіть під блокуючим JS).
- **PNG-експорт** підміняє глобальний `ctx` на offscreen + `renderW/renderH` (тому `ctx` оголошено як `let`). Кеш маршрутів інвалідуємо через `ROUTE.sig = ""`.
- Канвас перемальовується через `window.resize` + `ResizeObserver` на `#canvas-wrap`.

### Адаптивність (breakpoints у `style.css`)
- Топбар: `flex-wrap: wrap` завжди; інструменти — лише іконки завжди.
- `≤1280px`: ховаються підписи кнопок-дій, текст бренду, ім'я користувача.
- `≤1040px`: вужчі панелі.
- `≤900px`: вертикальне компонування (мобільні/планшети), палітра — горизонтальна стрічка, повноширинний канвас.
